# 가격제한폭 확대 이벤트 처리

2026-09-12 구현. 기준은 이 디렉터리의 `접속표준서(정보분배-UDP_TCP실시간)_v1.341-배포용.xlsx`에 있는 인터페이스 목록·정의서·가격표시정보다. 확대 예정과 실제 적용을 구분하며, 가격제한폭 확대를 CB 거래정지로 해석하지 않는다.

## 지원 전문과 처리 경로

| 전문 | 의미 | 엔진 처리 |
|---|---|---|
| `V1…F`, IFMSRPD0043, 65바이트 | 실제 가격제한폭 확대 | 종목·보드별 상/하한 단계와 적용 가격 갱신 |
| `M4…F`, IFMSRPD0019, 83바이트 | 장운영 스케줄, 확대 조건·예정 시각 | 원래 종목·상품·그룹 범위와 함께 별도 보관 |

V1 지원 정보구분은 `01F, 02F, 03F, 04F, 05F, 08F, 09F, 11F, 12F, 13F, 15F, 16F`다. M4는 `01F`~`16F`의 파생 전문과 현물 `01S/02S/03S/04S/01Q/01X`를 지원한다. CB·세션 제어도 추가했다. 제도·UDP 채널·전체 전문 필드·배포 연결 사항은 [CB·가격제한폭 통합 문서](CB_가격제한폭.md)를 참고한다.

`KrxUdpReceiver → DecoderSet::decode_krx_derivative → Broker → TradingEngine`으로 전달한다. 종목별 V1/M4는 해당 종목을 담당하는 엔진으로 라우팅한다. ISIN이 공백인 M4는 모든 엔진으로 전달하되 상품·그룹 범위를 보존한다. 그룹 통지를 모든 종목의 상태 변경으로 적용하지 않는다.

UDP ISIN 필터는 V1의 `15..27`, M4의 `31..43`을 사용한다. 그룹 M4는 종목 필터를 통과한다. TR 허용 목록을 사용하는 배포에서는 **기존 목록에 필요한 `V104F`·`M404F` 등을 추가**해야 한다. 소켓·멀티캐스트 구독 설정은 자동 변경하지 않는다.

디코더는 길이·종료 문자·TR 코드·종목코드·숫자·시각·단계·가격 범위를 검증한다. 파싱 오류가 나면 출력 버퍼를 부분 갱신하지 않는다. `04F/05F` 가격은 소수점 없는 8자리 정수(S0), 나머지 지원 V1 가격은 소수 2자리(S2)로 보관한다. **북의 가격 스케일로 변환한 뒤 비교해야 한다.** 특히 maker Parquet 북의 S2 가격과 주식선물 V1의 S0 가격을 직접 비교하면 안 된다.

## 상태 조회

[KrxMarketState](../../src/data/exchanges/krx/market_state.rs)는 실시간 엔진과 백테스트 엔진이 각각 소유한다.

- `engine.krx_market_state().price_limits(id, *b"G1", now)`는 결정 시각까지 수신한 제한가격을 반환한다.
- `engine.krx_market_state().schedules(now)`는 현재 KST 날짜의 수신 통지를 반환한다. 소비자가 종목·상품·그룹 범위를 확인해야 한다.
- 전략의 `IterationContext.krx_market_state`와 백테스트 `OverlayContext.krx_market_state`에서도 같은 상태를 조회할 수 있다.

V1 상한 단계와 하한 단계는 독립적으로 보관한다. 종목·보드·정보구분·KST 날짜가 같은 V1의 중복·역순 일련번호는 이전 상태를 덮어쓰지 않는다. M4는 같은 이벤트·범위의 최신 통지를 보관하고 더 이른 거래소 이벤트 시각의 지연 통지를 무시한다.

확대 예정 시각이 지나도 M4만으로 제한가격을 바꾸지 않는다. 최초 V1 수신 전과 다음 KST 날짜에는 `price_limits()`가 `None`을 반환한다. `None`은 ‘정상 1단계’가 아니라 **미확인**이다. 수신 시각보다 이른 시각으로 조회해도 반환하지 않는다. 이 저장소는 과거 상태 이력을 제공하는 데이터베이스가 아니다.

현재 만료 기준은 KST 달력 날짜다. 야간 세션의 영업일 귀속이나 재접속 후 상태 복원은 별도 세션·마스터 연동이 필요하다. 최근 관측값을 제공하는 저장소이며, UDP 패킷·엔진 큐의 유실 감지/복구까지 보장하지 않는다.

## 백테스트와 후속 전략 연결

`BackTestFeed::FlatFile`에 실제 수신 시각과 V1/M4 원문이 있으면 같은 디코더와 상태 저장소를 거쳐 재생한다. 예정 통지 이후라도 V1을 수신하기 전에는 확대 적용을 알 수 없다.

현재 `KrxParquetFeed`는 호가·체결만 읽으며, **V1/M4 저장·변환·Parquet 재생은 아직 연결되지 않았다.** 기존 하이닉스 Parquet 결과에 이 이벤트가 자동으로 추가되는 것은 아니다. 호가 소실이나 KIND 공시 시각으로 과거 이벤트를 만들어 넣지 않는다.

이벤트 수신·해석·상태 전달과 CB·세션 기반 연속매매 제어를 구현했다. 정지·단일가 중 신규/정정 주문과 연속매매 데이터 입력을 차단하고 취소는 허용한다. 재개 후 새 호가를 받아야 주문을 허용한다. 그룹 통지는 `register_krx_scope`로 명시적으로 등록한 범위에만 적용한다. 다음은 별도 작업이다.

- `A004F` 마스터에서 장 시작 제한가격 초기화와 재접속 시 상태 복구.
- 상품·그룹 마스터와 app 설정에서 `register_krx_scope`를 호출하는 자동 연결, 단일가 매처.
- 하이닉스 maker의 신규 매수·EWMA 중단/복구, 선물 앵커와 독립된 필수 청산.

이 변경은 관측된 거래정지 중 주문·체결을 제한하지만 maker의 앵커·EWMA·필수 청산 정책은 별도다. 전략 대응 원칙은 fractal-engine `apps/backtest/maker-test/krx_stock_making_strategy.md` 를 따른다.

`cargo test --offline --test engine --test backtest --test unit`
